# Участие в проекте

Баг-репорты, идеи и пул-реквесты приветствуются. Общаться в issues и пул-реквестах можно по-русски и по-английски.

## Сообщить об ошибке или предложить идею

Откройте [issue](https://github.com/SergeyShk/ruSyntax/issues/new/choose) по шаблону. Для ошибки нужны предложения или код, на которых она проявляется, ожидаемый и фактический результат, версии ruSyntax, Python и ОС. Для идеи - какую задачу вы решаете и почему текущих возможностей не хватает.

## Окружение разработки

Проект использует [uv](https://docs.astral.sh/uv/) для управления зависимостями, [maturin](https://www.maturin.rs/) для сборки модуля на Rust и [ruff](https://docs.astral.sh/ruff/) для линтинга и форматирования. Требуются Python 3.11 или новее и [Rust](https://www.rust-lang.org/tools/install) 1.88 или новее.

```bash
git clone https://github.com/SergeyShk/ruSyntax.git
cd ruSyntax

make deps                   # создать окружение, установить все зависимости и собрать модуль на Rust
uv run pre-commit install   # хуки: линтеры на коммите, тесты на пуше
```

Модуль на Rust собирается при установке пакета в окружение; `uv run` пересобирает его сам, когда меняются файлы `crates/` или `Cargo.toml`. Полный список команд - `make help`.

## Проверки

Перед отправкой пул-реквеста должны проходить:

```bash
make lint        # ruff check --fix, ruff format (код и Python в Markdown), mypy, cargo fmt, cargo clippy
make test-cov    # pytest с примерами из докстрингов (doctest) и порогом покрытия, cargo test
make docs-build  # mkdocs build --strict, если менялась документация
```

Лицензии крейтов Rust, собранных в модуль, лежат в `THIRD-PARTY-NOTICES.txt` и попадают в колеса; после изменения `Cargo.lock` файл пишется заново командой `uv run python scripts/notices.py`, иначе тест `test_third_party_notices` упадет.

То же самое выполняет CI на Python 3.11-3.15, 3.14t и 3.15t без GIL (Linux), на Windows и macOS для одной версии Python, а также проверяет сборку на минимальной версии Rust 1.88. Повышая минимальную версию Rust, меняйте ее в `rust-version` в `Cargo.toml`, в задаче `msrv` в `ci.yml`, на страницах установки документации и в README.

## Что ожидается в пул-реквесте

- **Одна тема - один пул-реквест.** Правки не по теме лучше вынести отдельно.
- **Тесты.** Новый код покрыт тестами: код на Rust - тестами в `crates/`, API для Python - тестами в `tests/`, покрытие Python не ниже 90 %.
- **Документация.** Документация двуязычная - русская страница `docs/*.md` и английская `docs/*.en.md` рядом, тест `tests/test_docs.py` следит, чтобы у них совпадали разделы, якоря и ссылки. Примеры в докстрингах и документации показывают фактический вывод.
- **Совместимость.** Изменение Python API, разборов и формата модели - только с пояснением в описании пул-реквеста: оно попадет в заметки релиза.
- **Стиль.** Код Python форматируется ruff, типы проверяются mypy; код Rust форматируется rustfmt и проверяется clippy без предупреждений (`make format`, `make lint`). Докстринги и комментарии - на русском, имена в коде - на английском. Комментарии в коде не дублируют то, что видно из него самого.
- **Коммиты.** Сообщения на русском в повелительном наклонении: «Добавить …», «Исправить …», «Убрать …».

Описание пул-реквеста отвечает на два вопроса: что сделано и почему. Если пул-реквест закрывает issue, укажите его номер.

## Как устроен репозиторий

- `crates/rusyntax/` - ядро анализатора на Rust; публикуется на crates.io.
- `crates/rusyntax-py/` - модуль Python `rusyntax._rusyntax` на PyO3, отдельно не публикуется.
- `python/rusyntax/` - пакет Python поверх модуля.
- `tests/` - тесты пакета Python; `tests/test_docs.py` - два языка документации.
- `docs/` - документация MkDocs (Material), `mkdocs.yml` - навигация и перевод ее на английский.
- `scripts/` - проверка установленного пакета перед публикацией (`smoke.py`), лицензии крейтов модуля (`notices.py`).
- `.github/workflows/` - CI (`ci.yml`), публикация (`publish.yml`), документация (`docs.yml`: сайт публикуется по тегу релиза).

Исходники (sdist) собираются из файлов под git (`sdist-generator = "git"`), чтобы `maturin build --locked` работал на них со всеми крейтами рабочего пространства. Собрать их можно только в копии репозитория: `uv build` и `python -m build` на распакованном архиве исходников падают, а `pip install` и `maturin build` из него работают везде.

Версия пакета хранится в `pyproject.toml` и в `Cargo.toml` в записи semver (`0.1.0.dev1` - `0.1.0-dev.1`); их совпадение проверяет тест. Тег версии запускает `publish.yml`: колеса и исходники собираются один раз, проверяются на всех платформах и публикуются на TestPyPI, а версия без `.devN` затем - на PyPI и крейтом на crates.io. Если публикация прервалась, перезапускайте только упавшие задания (Re-run failed jobs): уже принятые файлы и опубликованный крейт повторный запуск пропускает. Изменения описываются в заметках GitHub Release, отдельного файла CHANGELOG нет.
