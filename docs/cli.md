# Команда rusyntax

``` bash
rusyntax [параметры] [файл ...]
```

Команда разбирает текст из файлов или стандартного ввода и пишет [CoNLL-U](https://universaldependencies.org/format.html): для каждого слова - лемму, часть речи и признаки, вершину и тип связи [Universal Dependencies](https://universaldependencies.org/). Она ставится вместе с пакетом (`pip install rusyntax`) и запускается и как `python -m rusyntax`. Текст делит на предложения и слова сегментатор [anySeg](https://github.com/SergeyShk/anySeg), части речи и признаки ставит морфологический анализатор [ruMorph](https://github.com/SergeyShk/ruMorph) - те, что установлены вместе с пакетом, - поэтому результат тот же, что у [`parse_text`](parser.md#parse_text), и скорость та же: один поток, около 29 тыс. слов в секунду вместе с морфологией ([Сравнение](performance.md)).

``` bash
echo "Мама мыла раму." | rusyntax
```

```
# newdoc
# newpar
# sent_id = 1
# text = Мама мыла раму.
1	Мама	мама	NOUN	_	Animacy=Anim|Case=Nom|Gender=Fem|Number=Sing	2	nsubj	_	_
2	мыла	мыть	VERB	_	Aspect=Imp|Gender=Fem|Mood=Ind|Number=Sing|Tense=Past|VerbForm=Fin|Voice=Act	0	root	_	_
3	раму	рама	NOUN	_	Animacy=Inan|Case=Acc|Gender=Fem|Number=Sing	2	obj	_	SpaceAfter=No
4	.	.	PUNCT	_	_	2	punct	_	_
```

## Параметры { #options }

| Параметр | По умолчанию | Описание |
| :------- | :----------- | :------- |
| `-i`, `--input` | `text` | [Вход](#input): `text`, `conllu` |
| `-m`, `--model` | модель пакета | Файл модели ruSyntax, как `Parser(path)` |
| `-o`, `--output` | стандартный вывод | Файл результата; `-` - стандартный вывод |
| `-h`, `--help` | | Показать справку |
| `-V`, `--version` | | Показать версии ruSyntax, anySeg и ruMorph |

Файлы читаются по очереди, без файлов и вместо `-` - стандартный ввод; вход - в UTF-8: файл в другой кодировке (cp1251, UTF-16) не разбирается, а отдельная строка с неверными байтами разбирается с U+FFFD вместо них. Значение параметра пишется отдельно или слитно: `-i conllu`, `-iconllu`, `--input=conllu`; имя файла, которое начинается с дефиса, пишется после `--`. Текст разбирается по абзацам, CoNLL-U - по предложениям: результат выводится, как только абзац или предложение закончит пустая строка или конец входа, - в терминал сразу, а в канал и файл всякий раз, когда команда ждет следующую строку входа; ее можно держать открытой и подавать текст абзацами.

В Windows PowerShell 5.1 перенаправление `>` и конвейер (`Get-Content text.txt | rusyntax`) портят кириллицу: передавайте файл аргументом, а результат пишите параметром `-o` (в PowerShell 7 работают и они). Текст из `echo` в cmd приходит в кодировке консоли: перед ним нужна команда `chcp 65001`. Шаблоны файлов (`*.txt`) cmd и PowerShell не раскрывают.

## Вход { #input }

- `text` - текст: пустая строка заканчивает абзац. Токены и предложения находит сегментатор anySeg по соглашениям Universal Dependencies, на которых обучены модели ruMorph и ruSyntax; предложение может переходить через перевод строки. Абзац без пустых строк длиннее 256 КБ (файл с предложением в строке, одна длинная строка) anySeg делит на куски по границам предложений: память не растет с длиной входа, а номера предложений и абзац продолжаются через куски; предложение длиннее 256 КБ режется.
- `conllu` - [CoNLL-U](https://universaldependencies.org/format.html) с частями речи (UPOS) и признаками (FEATS): заполняются столбцы HEAD и DEPREL, а остальные столбцы, комментарии, многословные токены и пустые узлы остаются как есть (столбец DEPS тоже не меняется). Часть речи - одна из 17 частей речи UD заглавными буквами. Предложение, в котором частей речи нет ни у одного слова, сначала разбирает ruMorph: заполняются LEMMA, UPOS и FEATS, как у команды `rumorph -i conllu`; часть речи не у всех слов предложения - ошибка.

``` bash
printf '1\tМама\t_\tNOUN\t_\tCase=Nom\t_\t_\t_\t_\n2\tспит\t_\tVERB\t_\t_\t_\t_\t_\t_\n' | rusyntax -i conllu
```

```
1	Мама	_	NOUN	_	Case=Nom	2	nsubj	_	_
2	спит	_	VERB	_	_	0	root	_	_
```

Разбор на своих частях речи и признаках показывает, как анализатор работает с идеальной морфологией, но обучен он на разметке ruMorph и с ней точнее всего. Чтобы заменить в файле CoNLL-U морфологию на разметку ruMorph и разобрать его, команды соединяются конвейером:

``` bash
rumorph -i conllu -f conllu gold.conllu | rusyntax -i conllu > parsed.conllu
```

## Вывод { #output }

CoNLL-U, как его пишет anySeg. У входа `text` - как у команды `rumorph -f conllu` и с заполненными HEAD и DEPREL: файл начинает комментарий `newdoc`, абзац - `newpar`, у предложения - комментарии `sent_id` (номера идут подряд по всем файлам) и `text`; в MISC - `SpaceAfter=No` у токена, за которым в абзаце нет пробела, и `SpacesAfter`, если там не один пробел. У входа `conllu` предложение выводится как прочитано, с новыми вершинами и связями. Строки кончаются LF, текст - в UTF-8.

## Коды выхода { #exit-codes }

| Код | Когда |
| :-- | :---- |
| 0 | Успех, в том числе если вывод закрыт раньше конца (`rusyntax text.txt \| head`) |
| 1 | Входной файл не найден, не читается или не в UTF-8, строка не в UTF-8 (она разбирается с U+FFFD), неверная строка CoNLL-U или незнакомая часть речи; предложения до ошибки разобраны, остальные файлы тоже |
| 1 | Модель не читается, файл вывода не создается или совпадает с входным файлом или файлом модели; ничего не разбирается |
| 1 | Ошибка записи; разбор останавливается |
| 2 | Неверные параметры |

Сообщения об ошибках пишутся в стандартный поток ошибок.
